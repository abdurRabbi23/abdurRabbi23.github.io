02 / Featured project

Safe robotic grasping with constrained deep reinforcement learning

B.Sc. thesis · KUET · 2025–2026

Comparative evaluation of constrained vs. unconstrained deep RL for safe robotic grasping on a UR5e manipulator in simulation.

  • Reinforcement learning
  • PPO / PPO-Lagrangian
  • NVIDIA Isaac Sim
  • Isaac Lab
  • Python
  • Linux
>80%lower average safety cost
~99.9%lift success, same as the baseline

// Problem

A robot arm trained with reinforcement learning can learn to grasp well and still behave unsafely along the way, for example by moving through near-singular poses where it loses dexterity. Adding a penalty to the reward is the usual fix, but it gives no guarantee. Can stating safety as an explicit constraint make a learned grasping policy safer without making it worse at the task?

// Approach

  • Built a UR5e pick-and-lift task with a ROBOTIS RH-P12-RN gripper in NVIDIA Isaac Lab.
  • Defined a safety cost that penalizes approaching kinematic singularities (the main constraint), joint limits, and the table.
  • Compared standard PPO against constrained PPO (PPO-Lagrangian) at two safety budgets, plus a control arm to isolate the effect of the constraint itself.
  • Trained every method on 5 independent random seeds and evaluated the frozen policies on 15,000 episodes each.

// Results

  • The constrained agent cut the average safety cost by more than 80% while keeping the same ~99.9% lift success as the unconstrained baseline.
  • Its biggest effect was on consistency: the unconstrained agent's safety varied wildly from one training run to the next, while the constrained agent's stayed in a tight, predictable band.

// What I learned

  • Unconstrained RL doesn't have one safety level. It has a spread, and which one a training run lands on is close to luck, so multi-seed evaluation is essential.
  • Isolating one variable with a control arm is what makes a comparison trustworthy.
  • Practical Isaac Sim/Isaac Lab work on Linux: environment design, reward and cost shaping, and validating simulated geometry against manufacturer specs.

Automated Paper Grading and Dispensing System

2025 · 5-member team · MTE 4108

A Raspberry Pi machine that grades exam sheets with OCR and feeds them out one sheet at a time.

  • Raspberry Pi
  • NEMA17 stepper
  • Lead screw
  • SolidWorks
  • Google Cloud Vision
Read more
  • Problem: Grading paper exams by hand is slow, repetitive and error-prone.
  • The system: A camera captures each answer sheet. OCR (Google Cloud Vision) reads the answers and checks them against a stored key, and the score is shown on a laptop. A roller mechanism then dispenses the graded sheet and feeds the next one.
  • My role: I designed the NEMA17 lead-screw paper-feed mechanism, which lowers the roller carriage by 0.12 mm per sheet (the thickness of 100 GSM paper), and integrated the Raspberry Pi control for the OCR grading pipeline.
  • Result: Built and demonstrated as a working prototype (MTE 4108 Design of Mechatronic Systems sessional).

Gesture-Controlled Car

Solo project

A four-wheel car driven entirely by hand gestures seen through a webcam. No remote, no joystick.

  • Python
  • OpenCV
  • MediaPipe (cvzone)
  • ESP32
  • Wi-Fi (UDP)
  • L298N
Read more
  • Problem: Control a vehicle naturally, without any handheld controller.
  • How it works: A Python program uses OpenCV and MediaPipe hand tracking (cvzone) to count the raised fingers on the webcam feed. Each count maps to a drive command, which is sent over Wi-Fi (UDP) to an ESP32 on the car. The ESP32 drives four gear motors through an L298N motor driver, powered by three 18650 Li-ion cells.
  • Result: Drove the real car in real time using finger-count gestures.
  • My role: Solo. I built the vision software, the ESP32 firmware and the car.
